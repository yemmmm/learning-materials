# 大模型基础扫盲分享大纲

建议标题：大模型常见概念 从日常使用到 AI 应用开发

面向人群：开发、测试、运维、产品、架构等 IT 相关行业人员，具备基本软件与互联网知识，无需机器学习背景。

建议时长：60 分钟分享，另留 10 分钟交流。下列章节中的例子计入分享时间；延伸词汇按听众兴趣选讲。

日期：2026-11-16。

分享目标：让听众能读懂 AI 产品与技术文档中的常见术语，解释日常使用中的典型现象，并理解一个 AI 应用如何连接模型、资料和业务系统。

## 1 认识大模型

**引入场景：聊天、写代码、生成图片都叫 AI，它们的能力从哪里来？**

- 概念位置：人工智能（AI）、机器学习、深度学习、生成式 AI、大语言模型（LLM）之间的关系。
- 模型与应用：模型提供基础能力；应用还组织界面、资料、工具和业务流程。
- 训练与推理：用“学习阶段”和“使用阶段”解释预训练、后训练、推理；介绍常见自回归语言模型逐步生成 Token 的基本方式。

举例：同一个模型分别用于聊天助手、代码助手和客服系统，实际体验为何不同。

讲述重点：训练会调整模型参数；日常对话主要是使用已有模型进行推理。训练与推理的基础概念可参考 [Hugging Face LLM 课程](https://huggingface.co/learn/llm-course/chapter1/4)。

## 2 理解一次对话

**引入场景：为什么聊天久了会忘事？为什么长文档可能放不进去？**

- Token：模型处理文本的基本单位；它与汉字、单词、字符数没有固定的一一对应关系。
- Prompt 与消息：提示词是什么；系统指令、用户问题、历史回答分别提供哪些信息。
- Context Window：上下文窗口限制一次处理的信息量；历史消息、资料和工具返回也会占用空间。
- Memory：区分当前上下文、应用保存的聊天记录，以及应用再次检索并提供给模型的长期记忆。

例子：展示一句中文、一段英文和一小段代码的分词结果，再画出一轮对话实际携带的信息。

讲述重点：能保存聊天记录、能放入当前上下文、能准确利用其中的信息，是三个不同能力。上下文管理可参考 [Anthropic 上下文工程说明](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)。

## 3 把需求说清楚

**引入场景：同样让 AI 整理会议纪要，为什么结果差异很大？**

- Prompt Engineering：说明任务目标、必要背景、约束条件和输出格式。
- Zero-shot 与 Few-shot：直接描述任务，以及提供少量输入输出示例，两种常见提示方式。
- Context Engineering：进一步组织每次调用需要的指令、资料、历史记录和工具信息。
- Temperature：理解采样随机性；降低随机性不能保证事实正确，具体可调参数取决于模型和接口。
- 结构化输出：让程序获得符合约定结构的数据；区分“要求输出 JSON”和接口提供的 Schema 约束能力。

例子：把“帮我整理一下”改成“提取决策、负责人、截止时间；缺失信息标为未提供；按指定字段输出”。

讲述重点：任务表达、信息供应和结果格式共同影响可用性。提示与上下文的关系可参考 [上下文工程说明](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)；采样概念可参考 [Hugging Face 推理课程](https://huggingface.co/learn/llm-course/chapter1/8)。

## 4 理解能力与边界

**引入场景：界面上的“上传图片”“联网搜索”“深度思考”分别在做什么？**

- 多模态：文本、图像、音频、视频等输入输出形式；识别输入与生成输出是不同能力。
- 知识截止与联网检索：区分训练中获得的知识，以及调用时从外部获取的信息。
- 推理模型与思维链（CoT）：理解多步求解和推理计算；展示的思考文字不能单独证明答案正确。
- 幻觉（Hallucination）：认识编造事实、来源、接口或不存在的功能等典型现象。

例子：给出报错截图，让 AI 解释可能原因，再提供软件版本和官方文档，比较哪些判断获得了证据支持。

讲述重点：分别检查输入是否识别正确、信息是否有依据、推导和最终结果是否成立。

## 5 接入自己的知识

**引入场景：怎样让 AI 根据公司内部的 VPN 文档回答问题？**

- RAG（检索增强生成）：先查找相关资料，再把资料交给模型生成答案。
- Embedding：把内容表示为向量，用于衡量相似性；用“词不一样，但意思接近”的提问解释语义检索。
- 认识一条常见知识库流程：文档切分、建立索引、检索、重排序、组织上下文、生成回答并关联来源。向量检索是常用方式，关键词和混合检索也可以参与。
- Fine-tuning（微调）：通过训练调整模型参数，常用于改善特定任务表现或输出行为。
- Prompt、RAG、微调的选择：分别从任务描述、外部知识和模型行为三个角度理解，按问题组合使用。

例子：用户问“在家连不上内网怎么办”，资料标题是“远程接入配置指南”；解释为何检索能找到它，以及检索失败会怎样影响回答。

讲述重点：上传文档可能触发不同处理方式；使用知识库检索通常不会因此更新模型参数。RAG 的基本思想可参考 [RAG 原始论文](https://arxiv.org/abs/2005.11401)。

## 6 从回答问题到执行任务

**引入场景：从“告诉我如何报障”到“查询状态并创建工单”，多了哪些组件？**

- Tool Calling / Function Calling：模型提出调用什么工具、传什么参数，应用或运行环境实际执行，再把结果交回模型。
- Workflow：由程序预先定义主要步骤与分支，例如“分类 → 检索 → 回答 → 转人工”。
- Agent：由模型根据目标和执行反馈，在一定范围内动态选择下一步与工具；实际系统可以结合 Workflow 和 Agent。这里采用 [Anthropic 对工作流与 Agent 的区分](https://www.anthropic.com/research/building-effective-agents)。
- MCP：认识 AI 应用连接外部数据和工具的标准协议，理解它与具体业务接口的关系。参考 [MCP 官方介绍](https://modelcontextprotocol.io/docs/getting-started/intro)。
- Skill：以 Agent Skills 格式为例，认识可复用的任务说明、脚本和参考资料包。参考 [Agent Skills 官方介绍](https://agentskills.io/home)。

例子：IT 支持助手先查 VPN 文档，再调用接口查询服务状态，最后创建工单并获得工单编号。

讲述重点：工具提供可执行能力；流程或 Agent 组织任务；MCP 规范连接方式；Skill 封装执行某类任务的方法。用工具返回的实际结果判断动作是否完成。

## 7 认识调用与成本

**引入场景：网页里问一句话很简单，接入自己的应用后要关注什么？**

- API 与 SDK：应用怎样向模型服务发送请求、接收文本或结构化结果。
- 流式输出（Streaming）：边生成边接收；区分首个结果的等待时间与完整任务耗时。
- Token 用量与计费：认识输入、输出及部分服务中的缓存、推理用量项，结合具体接口的计量规则理解账单。
- 多轮与多次调用：一次用户任务可能包含历史上下文、检索、工具交互和多个模型请求。
- 限流与并发：认识请求数、Token 吞吐限制及其对应用体验的影响。

例子：对比“一轮摘要”和“多次查询再总结”两种任务，画出请求次数、输入内容和等待时间的差异。

讲述重点：同时看单次请求和完整任务的成本与耗时。首 Token 延迟等指标可参考 [Hugging Face 推理课程](https://huggingface.co/learn/llm-course/chapter1/8)。

## 8 判断效果与选择方案

**引入场景：两个模型都能流畅回答，怎样决定用哪个？**

- Eval 与 Benchmark：认识业务任务评测和公开基准测试各自回答的问题。
- 选择维度：任务正确率、信息依据、工具执行成功率、稳定性、延迟和成本。
- 部署方式：认识托管 API 与本地部署，结合数据使用要求和运维能力理解选择。
- 最小评测示例：用一组真实、可判定结果的问题比较方案，记录失败情形。

例子：同一组 VPN 问题中，包含文档已有答案、需要查询实时状态、信息不足三类情况，比较系统能否采取合适行动。

讲述重点：把模型能力放进实际任务中评价，判断整个应用是否达到使用要求。

## 分享组织方式

- 每章按“常见问题 → 概念解释 → 一个例子 → 容易混淆的地方”展开。
- 日常例子使用会议纪要、长文档问答、报错截图；开发例子统一使用 IT 支持助手，逐步加入知识库、状态查询与工单创建。
- 计划安排三个短演示：查看 Token 分词、比较提示词与参考资料的作用、展示工具调用到实际结果的过程。实际演示材料在讲稿制作时准备。
- 交流环节可讨论：聊天记录为什么不等于模型已经学会、公司知识库为何检索不到、Agent 的成本为什么可能高于一次聊天。
