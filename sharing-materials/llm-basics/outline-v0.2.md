# 大模型常见概念：一个模型如何成为 AI 助手

版本：v0.2。日期：2026-11-18。

面向开发、测试、运维、产品与架构等 IT 从业者，无需机器学习背景。按约 60–70 分钟分享组织，另留交流时间。讲述主线：模型是什么、怎么运行和对话、怎么做成应用、怎么获取资料和调用工具、怎么成为 Agent。

以“公司差旅助手”贯穿应用部分。公司制度、汇率、发票和工具响应均为明确标注的教学示例，不调用真实业务系统。

本版重新组织内容，不沿用 v0.1 的章节逻辑。保留 v0.1 导出，不覆盖。每页提供可阅读的解释、实例、图表或截图，并配逐页讲稿；正文避免只有口号或孤立词语。

## 1. 先认识主角：大语言模型

介绍 AI、机器学习、神经网络、深度学习、语言模型与 LLM 的关系。NLP 是任务领域，不是严格包含链中的一层；早期语言模型也可以基于统计方法。

呈现：概念关系图，配分类、抽取、翻译、摘要、问答、生成等输入输出示例。先建立整体地图，后面再补多模态与其他模型。

## 2. 生成机制：Token、训练与推理

解释 Token、Token ID、参数、上下文。以主流自回归文本模型为例讲逐步生成下一个 Token。训练调整参数，推理使用已有参数；Transformer 与 Attention 点到为止。

呈现：真实分词示例、逐步生成演示，以及训练与推理对照。Token 不固定等于一个汉字或单词。

## 3. 使用方式：API 与自行部署

开发应用通常可以调用托管 API，也可以自行部署可获得权重的模型。两条路线最终都向应用提供推理能力。开放权重模型也可以通过托管 API 使用。

介绍开放权重、开源与许可证：拿到权重不代表训练数据和训练代码全部公开，也不代表使用不受许可约束。

呈现：两条使用路线与责任对照，不展开采购建议。

## 4. 模型仓库里有什么

介绍配置、权重、分词器三类组成：config.json 声明类型与结构配置，配合模型实现代码构建计算过程；*.safetensors 保存权重张量；tokenizer.json、tokenizer_config.json、vocab.json、merges.txt 等保存分词规则和词表，文件组合因模型而异。

呈现：优先使用 Hugging Face 官方模型仓库真实截图，三类文件标注，配配置片段；若浏览器无法访问，使用附原始链接的官方清单摘录，并明确标注非网页截图。避免把三个概念固定对应到三个文件，也避免把权重文件等同于完整网络实现。

## 5. 模型名称与规格

介绍模型家族、版本、参数规模、Dense/MoE、用途、数值精度。B 表示十亿参数，MoE 区分总参数与激活参数；激活参数不能直接替代部署内存需求。

呈现：模型名拆解、代表性公开模型规格表、Dense/MoE 对照。资料注明核对日期，未知参数标未公开，不宣称完整覆盖或最新排行。

## 6. 常见变体与训练名词

量化：较低数值精度表示权重或计算数据。蒸馏：利用教师模型输出等信号训练学生模型。SFT：输入与期望输出的监督微调。RLHF：利用人类反馈形成的奖励信号进行强化学习。LoRA：参数高效微调方式，可用于 SFT 等过程。

呈现：按改变对象与解决问题分组。量化、蒸馏、SFT、RLHF、LoRA 不属于同一分类维度，彼此可能组合。

## 7. 推理框架与服务

解释框架如何加载配置、权重与分词器，执行生成，以及服务层怎样提供 API。简要认识 vLLM、SGLang、llama.cpp，不展开安装。

呈现：文件、引擎、服务、应用的加载与调用流程。

## 8. 从续写到对话：预训练、后训练与聊天模板

先介绍预训练：从大量数据学习语言规律和广泛能力，得到基础模型。再介绍后训练：在基础模型上进一步训练，改善指令遵循、对话、任务表现与偏好等；SFT、RLHF 是常见方法，具体配方因模型而异。

重点展示 SFT 如何使用按对话模板组织的输入与期望回复，让模型学习在 assistant 位置按要求回答、输出约定形式。SFT 既影响回答行为，也帮助学习角色与格式，但不保证每次输出都满足严格 Schema。

调用时由应用使用对应 chat template，将 system/user/assistant 消息序列化为模型预期的 Token 序列；不同模型使用不同标记。增加 role 标签不能独自替代训练。

呈现：训练数据的输入与目标对照；messages 数组与实际模板文本并排；第二轮对话如何携带历史。示意 ChatML 标记时注明格式依模型而异。

## 9. 常见局限

介绍幻觉、训练知识过时、不知道未提供的内部资料、精确计算和长上下文信息利用的局限。

呈现：差旅助手的四个失败场景，对应实时信息、内部证据、计算能力和有效上下文的缺口。后续逐个补齐，不声称任何单一方案消除幻觉。

## 10. 从模型到最小应用

应用接收问题、管理会话、组织输入、调用模型、处理输出并展示结果。解释模型、聊天产品与业务应用的区别。

呈现：一张可以逐步扩展的最小应用架构图。后面把检索、工具和自主循环加到同一业务场景中。

## 11. 提示词与上下文工程

以“回答正确就给 100 美元”作流行提示技巧的趣味例子，不暗示稳定效果。介绍任务目标、约束、输出格式和 Few-shot。上下文工程扩展到每一步的指令、历史、资料、工具定义、工具结果的选择、组织与更新。

呈现：模糊要求、清晰任务与示例、补充资料的输入对照；上下文组成图。提示词工程仍是上下文工程的一部分。

## 12. RAG、Embedding 与检索

RAG 是回答前检索资料，再依据资料生成答案。拆开离线资料准备与在线回答：解析、切分、索引；检索、重排、上下文组装、生成与来源。

必须提醒：Token ID 与 Embedding 虽然都由数字表示，但含义不同。Token ID 是分词器给词元分配的离散编号，编号数值的接近不表示语义接近；Embedding 是一组浮点特征，可以在适配的模型与度量下用于相似性比较。区别内部 Token Embedding 与用于检索的句子/文档 Embedding。向量空间位置只做教学示意，真实向量通常有很多维。

介绍关键词、向量、混合检索与 Reranker。RAG 不等于向量数据库；通常不更新生成模型权重；检索或解释失败仍会导致错误。

呈现：双阶段 RAG 图、Token ID 与向量对照、语义接近示例、带文档依据的回答。

## 13. Function Calling 与 Tool

模型依据工具描述生成名称和参数，应用实际执行，把结果交回模型，模型再生成回答。Tool 是具体可调用能力。检索也可以封装为工具，RAG 与工具调用可以组合。

呈现：查汇率、计算费用的工具定义、调用 JSON 与返回值；完整往返演示。请求执行与实际执行成功分开说明。

## 14. Workflow、ReAct 与 Agent

从“人或程序决定步骤”过渡到“模型根据目标与执行反馈动态选择下一步”。Workflow 预先规定主要路径，Agent 在约定范围内动态选择工具与行动；真实系统可以组合。

ReAct 是推理与行动交替的一种模式，不代表所有 Agent 的唯一架构。用可观察行动记录解释判断、工具调用、结果与下一步，不把示意文字当模型私有思维原文。

呈现：固定流程与循环对照，以及一项差旅报销任务的完整行动记录。

## 15. Harness

介绍围绕模型的运行与控制系统，术语边界依实现不同。包含任务状态、进度、记忆、上下文压缩、工具执行、错误处理、沙箱、权限、停止条件、预算、日志与检查。

呈现：围绕模型的系统组成，以及长任务在上下文切换时如何保存和恢复进度。记忆通常依赖外部存储与检索，压缩可能遗漏信息，沙箱限制执行环境。

## 16. Tool、MCP、Skill

Tool 提供可执行能力；MCP 提供应用连接工具与数据的标准协议，还可提供资源与提示模板；Skill 封装特定任务说明、知识及可选脚本模板，不必须依赖 MCP。

呈现：同一场景对照表、MCP 的 host/client/server 连接图、SKILL.md 目录与按需加载示例，最后组合起来。

## 17. 多模态与其他 AI 模型

介绍图片、音频、视频等输入输出，多模态输入与输出能力依模型而异。区分生成式语言模型、检索 Embedding 模型、Reranker、语音识别/合成、图像与视频生成等。

呈现：差旅助手读取发票、转写语音、检索制度、计算金额和生成报告，各步骤标出模型或普通程序。以完整应用图收束，并提供常见名词定位和参考资料。
