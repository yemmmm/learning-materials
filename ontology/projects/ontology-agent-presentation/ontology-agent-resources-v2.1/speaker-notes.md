## P06 · 六种方法怎样补足判断依据

本页明确对应 P04：提示词在第 1／5 步要求分别回答申请资格和退款前提；RAG 在第 3 步找 RET-DEMO-v1；工具在第 2／4 步取得签收、验收等事实并计算 120 小时；专家在第 3／4 步确认起点、字段及状态含义；本体在第 2—5 步提供已确认的定义、关系、条件及映射。微调通过训练改善售后任务适配，不是每次提问时的在线步骤，也不能提供当前政策和实时状态。六种方法并不互斥，RAG 可以检索本体，工具也可执行已编码规则。P05 的缺口是缺少可靠的含义与口径，不能单凭工具调用成功补足。

## P07 · 不同方法的局限性

这里没有证明本体是唯一方案。统一文档、业务词典、共享配置和规则服务也能解决共同口径。后面继续考察：跨对象、跨任务、跨系统的显式关系能否改善知识复用，收益是否值得维护投入。RAG 不局限于关键词匹配，本体也不能消除所有错误。

## P10 · 什么是本体（Ontology）

显式，指含义和关系被明确表达。领域，指有界的一块业务。共同使用，指不同人和程序可引用同一身份及定义。自然语言说明帮助理解，稳定身份和结构化关系支持定位与关联。只将制度文档改名为本体不会自动得到这些能力。这里区分三个层次：本体是形成的知识模型；本体建模的方法论指导怎样访谈、澄清、表达、验证与维护；围绕本体组织 Agent 和系统，是一种架构思路，宽泛地也可称为设计范式。工程本体这一产物与建立、使用它的方法分别说明。

自然语言说明帮助理解，稳定身份和结构化关系支持精确引用；仅把一段制度文字改名为“本体”并不自动获得这些能力。工程本体这一知识产物、建立它的方法论、围绕它组织系统的架构思路分别说明；后者可宽泛称为设计范式，不直接将本体本身定义为方法论或范式。W3C OWL 2 Primer

## P15 · 业务含义怎样表达与查询

RDF 是图数据模型，RDFS 是基础类型及层级词汇，OWL 提供更丰富的形式化语义，SPARQL 查询 RDF。OWL 可以有 RDF 表示，但所有 RDF 并不都是 OWL 2 DL 本体。

Turtle 教学代码：
@prefix ex: <https://example.org/returns/> .
@prefix rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#> .
@prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .
ex:ReturnRequest rdfs:subClassOf ex:AfterSalesRequest .
ex:RET-DEMO-v1 rdf:type ex:ReturnPolicy ; ex:appliesTo ex:StandardProduct .

这里只表达类型和关系。168 小时时间窗仍作为普通业务条件说明保留。

RDF 是数据模型，Turtle 是一种序列化语法；OWL 可有 RDF 表示，但不等于所有 RDF 都是 OWL 2 DL 本体。业务关系和说明可被机器读取，不代表其中所有业务条件都已形式化或可自动执行。完整代码放备注。技术来源

## P17 · 本体的优势与适用条件

收益依赖定义准确、读取充分、持续维护和消费正确。先选择一个跨环节问题，同条件比较正确性、维护与人工确认成本，不许诺必然优于 RAG 或自动消除幻觉。

共享配置和规则服务也能复用定义或执行判断。采用本体的理由应是跨对象、跨任务、跨系统的显式关联能改善实际理解与维护；简单固定任务可用更轻方案。收益依赖定义准确、读取充分、持续维护和消费正确，不许诺自动消除幻觉或必然优于 RAG。

## P22 · 七个视角检查同一业务模型

## P31 · 语义怎样连接 SQL 与 API

先读取获准语义和真实 schema，才能在定义、连接与口径约束下生成 SQL。业务库行列访问控制由外部系统负责。示例查询：
SELECT o.signed_at, p.category
FROM order_items oi
JOIN orders o ON oi.order_id = o.id
JOIN products p ON oi.product_id = p.id
WHERE o.id = :order_id AND oi.id = :item_id;

售后事实来自 GET /order-items/{id}/after-sales-context，三字段是 inspection_status、approval_status、refund_status。时间差由日期计算工具给出。真正提交由外部系统重检，操作受理不等于完成。上述接口不是 OntoWeave 新增接口。

SQL 在获准语义与真实数据结构（schema）约束下生成，业务数据访问控制由外部系统负责。时间差由消费者调用日期时间计算工具得到；实际提交由业务系统重检条件。退款回执的 `ACCEPTED` 仅表示请求受理，`SUCCEEDED` 才表示本例外部系统确认退款完成；均须按接口合同解释，不由 HTTP 成功或接口名称推断。
