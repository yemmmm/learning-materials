### R4.0-025 校验推理与业务规则专用建模能力阶段性退役

状态：2026-10-08 已按本条范围实施专用能力退役，并同步当前接口、Task／Profile／角色／
Skill、候选、Protocol、交接和恢复所用合同。开发回归及隔离真实接口验证通过；
未启动、继续或修复真实建模，未新增建模额度，未进行独立业务语义验收。
实施边界与证据见[交付记录](../delivery/records/2026-10-08-r4-0-025-retirement-delivery-record.md)。

**问题与目标**：现阶段优先完善业务资料澄清、概念与关系表达、确定性写入、实际读回及
受治理语义检索，取得真实建模质量与业务问题回答质量证据。SHACL 专用约束建模、OWL
自动推理及业务规则的脚本化／程序化合同与当前流程配合不足，增加了产物、调用与交接
复杂度。本条阶段性退役这些专用能力及其主流程依赖，保留业务知识和必要写入校验。
此决定不否定校验与推理的价值，也不认定它们是历史建模失败的唯一或主要原因。

#### 1. 退役能力与保留边界

| 能力 | 本期退役范围 | 继续保留 |
| --- | --- | --- |
| SHACL | 专用 Shape 创建／修改／读取与指导、SHACL 校验运行／报告消费，以及候选、提示、交接和验收对它们的要求 | 独立于 SHACL 的现有基础写入合同校验；普通概念、属性和关系表达 |
| OWL 图推理 | 自动一致性／分类／蕴含运行、推理派生结果及其专用读取／有效性状态、推理回执完成门 | 来源已确认并显式建模的分类、层级和关系；通用 RDF 存储与受治理检索 |
| 业务规则专用建模 | 专用 `rule_definition` 注解合同、规则脚本／语言／版本／执行环境的维护要求、程序化输入输出与求值／推导约定 | 普通业务规则概念、语义说明及与对象／Action／流程的关系；已确认条件、阈值、计算口径、范围、例外与未知 |

- 不再要求 Agent 创建 Shape、运行 SHACL／OWL、提交专用规则注解或编写业务脚本，
  不以缺少这些产物／结果判定建模未完成、模型缺陷或待补验能力。
- 业务规则仍是业务知识。例如“未验收工单不能关闭”“SLA 从报修时间开始计时”必须按
  资料正确表达并可检索；不要求将其包装为可执行规则或强制拆成程序化输入输出实体。
  源材料中的脚本可作为普通说明材料保留，不再维护专用脚本合同或要求 Agent 补写脚本。
- 退役的是自动推理机制，不按 `owl`／`rule`／`shape` 等名称批量删除资源或词汇。
  已确认的类型、子类与关系可以显式表达；不把未表达内容自动当作已推导事实。
- 保留 R4.0-022 已完成的旧执行器退役结果，不新增替代规则执行器、SHACL 替代体系、
  自研推理框架或能力切换／兼容模式。平台仍不自动执行业务脚本、产生业务结果或执行 Action。
- 保留已有模型中的普通业务知识与历史交付／验收记录；专用历史数据和共享依赖的实际
  保留边界已按实际依赖确定：保留历史记录、既有数据库模型／迁移和共享恢复结构，
  当前 scope／投影排除专用派生内容；不执行历史数据迁移或批量资源清理。

#### 2. 功能要求

**F1 — 全局规划与阶段选择（D1）**

- 通常复用已有业务切片作为推进阶段；“完整小链”是内容可消费的判断条件，不增加
  一套独立划分。仅切片过大或真实业务依赖跨切片时调整阶段边界。分阶段和早期公开
  反馈已有实现，本条不将它们重复登记为新增平台能力。
- 全局保留完整获准业务范围、逻辑切片、共享概念、依赖及剩余事项。Agent 在其中选择
  含义完整、可消费的小业务链；必要共享依赖随首链落地，后续复用真实身份。
- 全局规划不要求先完成全部详细候选或全部执行计划。每阶段应用前，核对本阶段定义、
  关系、共享引用、跨 Ontology 目标及依赖已由当前候选和获批计划覆盖；遗漏须先补齐。
  其他阶段尚未完成的内容持续记为剩余事项，不能通过移出计划静默缩小获准范围。
- 阶段不固定等同于一个切片、Batch 或 Ontology；批次依据实际依赖及部署上限安排。
  已批准且未变更的计划沿 R4.3-002／003 连续执行，不增加每个小批后的重复授权。
- 2026-10-13 采用纠正：Coordinator 首条阶段派单明确当前可交付业务链、必要共享依赖
  及全局待办；当前候选／计划完整性指该阶段的内容与真实依赖，不要求先完成全部场景
  详细设计。Modeling 在同一次阶段交接从获准原资料反查关键事实、关系方向、条件／
  例外和未知的候选去向，再从候选反查无依据断言；复用候选 item、交接说明和场景图
  note，角色只核对其获准可读资料，不用摘要冒充未读原件的完整性，不建逐字段台账。

**F2 — 写入与语义质量责任分开（D3）**

| 用途 | 责任与要求 |
| --- | --- |
| 候选及计划是否覆盖必要业务内容 | Modeling 作业务判断，Coordinator 审核范围及共享依赖，Protocol 核对计划转换；应用前完成，不用成功写入掩盖计划漏项 |
| 已批准计划是否正确应用 | 平台保证校验、有效 dry-run、原子应用与明确终态；工具保留回执身份、Attempt 及版本确认；Agent 正常收到成功后不例行全量读资源或逐条比对计划 |
| 表达、检索及业务回答是否正确 | 依据有明确业务目的的实际受治理读取、公开反馈、关联检查和最终独立验收判断；不能用回执代替语义证据 |
| 未确认成功的写入及历史恢复 | 沿 R4.3-014 和原恢复合同核对原尝试、已完成内容及受影响资源；不重放成功内容，不取消必要对账 |

若实际业务读取发现成功回执对应漏写、错写或绑定不一致，定位为平台缺陷并修复窄失败层；
保留原证据，必要时进入现有写入完整性恢复。不以增加 Agent 常驻全量核验补偿平台缺陷，
也不得将该核验改称“语义验证”后继续每批执行。R4.3-002—004 及旧设计中的“必要读回”
按本表解释，不再指成功后重复证明计划被忠实执行。

2026-10-13 信息保留增量：源明确支持的内容与尚待确认的业务含义分开，未知限定到具体
含义及影响范围；物理结构／样例出现不升级为业务规则、合法值全集或权限。确认状态与
候选、批准、应用等交付状态分开；本阶段 deferred 项说明具体原因、缺失能力及下一责任／
输入，同因事项可合并。只在现有表示合同和授权内交付已知部分，不能自行物化未批准映射，
也不能因有 deferred 处置就把本轮业务范围记为完整；沿用 R4.0-010／014 的边界。

**F3 — 成功回执与异常状态**

| 可观察状态 | 行为与结论 |
| --- | --- |
| 与当前获批计划、请求及 Attempt 对应的 `apply_atomic` 明确终态 `applied` | 记录已应用并继续；保留工具内身份／版本确认，不要求 Agent 再逐条证明写入 |
| `dry_run` 的 `validated` | 仅证明该版本上的验证结果，不当作应用；沿既有批准与有效证明执行 apply |
| `pending`、`applying`、`recovering`、超时、断线或成功身份／终态不能确认 | 保留未确认状态，沿原请求与原 Attempt 恢复或对账；不得换 key 重放可能已写入内容 |
| 明确 `validation_failed` 或 `failed` | 保留 findings 及实际失败层，沿既有可恢复反馈修正；不假定产生了成功模型，也不令整轮永久失败 |
| 历史／其他合同中的 `partially_applied` | 不当作当前完整原子计划成功；核对已应用与剩余范围，沿原合同处理，不整体重放 |

仅接收成功、HTTP 成功、工具 `COMPLETE` 或候选已发布均不自动构成应用成功或语义 PASS。
发现异常时只限制原恢复合同要求的受影响写入；不扩大成所有无关阶段永久停止。

**F4 — 有价值节点的公开反馈（D4）**

- 2026-10-13 采用纠正：首条可消费业务链明确应用后，Coordinator 具体请求 Delivery
  组织现有 public-feedback；Delivery 主动核对真实 materialization_progress 检查点、
  冻结身份和所选获准公开题，跟进实际读取及完整反馈正文，不等待最终生产交接。
- 第一条可消费小链明确成功应用后，尽早选择少量高价值获准公开题取得真实读取和回答。
  不要求先做完整资源／关系写入比对，也不等待所有场景完成或正式 production handoff。
- 后续由 Agent 结合新增关键规则、跨切片关系、共享语义变化及实际疑问判断时机和选题。
  不固定每批、每阶段问答，不固定题量，也不预先写死全部反馈节点。
- 复用现有批准／冻结公开题及反馈入口，保留题目版本、模型状态、实际读取、回答、未知
  及定位结果。入口能力未启用、检查点不完整或读取不完整时准确记未执行／PARTIAL，
  继续修正可恢复问题，不静默更改运行 Task 或伪造已反馈。
- 模型表达、检索取得和 Consumer 理解分别诊断；原因不足保留未确定。公开反馈只服务
  生产质量，隐藏题／答案保持隔离，用于修模的题不得重新当作隐藏盲测。

**F5 — 反馈绑定与提交窗口（D5）**

- Coordinator／Delivery 沿现有协作安排有界的实际反馈读取窗口；从窗口开始到前后绑定
  核对完成，暂停本轮新的 dry-run/apply 提交，先排空并处理未确认提交。Agent 仍可分析
  材料、准备候选和后续计划；读取结束后恢复正常提交及 D2 的依赖推进。
- 本期不新增快照、并发提交判定、调度框架或平台锁。该窗口是现有读取合同下的协作
  安排，不改成永久硬拒绝，不把整轮剩余建模冻结至最终独立验收。
- 实际发现模型绑定、提交记录或公开题绑定变化时，保留原结果并记过期／`superseded`；
  在新的有效状态上沿原入口重取必要反馈，不拼接不同状态证据，也不声称当前模型已验证。

**F6 — 质量修正与继续（D2）**

- 只暂停受影响内容及依赖它的阶段；与该缺口无依赖的工作仍可推进。共享概念发生改变
  时按真实使用关系判断影响，不以“另一个切片／Ontology”直接认定无依赖。
- 修正业务候选、审核变更、取得有效 dry-run 并 apply；原成功内容不重放。修正后复核
  受影响公开问题及关联，范围／端点变化时补足受影响覆盖，不机械重做所有未变化内容。
- 反馈读取窗口结束后依本条推进；未解决问题不因其他阶段继续而记通过，业务未知保持
  未知，不从数据库 Schema 或测试答案补造事实。

**F7 — 阶段结束与全局收口（D6）**

- 分别记录当前阶段已应用、已取得业务质量反馈及未验证／未解决事项。阶段候选及获批
  计划覆盖、依赖具备且收到明确成功回执后，可推进下一阶段；该推进不声明语义 PASS。
  已知问题仍按 F6 限制相关依赖，不强制每阶段取得公开问答通过才能继续。
- 全部获准范围完成后，核对全局语义覆盖、跨切片共享身份及一致性；按 R4.0-024 检查
  实际模型关联、处置游离候选和必要修正。最终检查不是每次成功 apply 的完整写入审计，
  候选不等于缺陷，有业务依据的独立定义及未知须如实处置，不为连通图而造关系。
- 未应用的获准内容、未检查范围及已确认缺陷不能被局部通过掩盖。读取不完整／原因
  未定保留 PARTIAL，已知未解决缺陷保留 REVISE；沿现有生产角色及交接顺序收口。
- 最终仍进入完整独立 Consumer／Judge 验收，按冻结题集、获准资料及实际平台读取判定。
  验收者不创建、继续或修复被验收 run；阶段反馈、生产自查或应用成功均不替代独立结论。

#### 3. 已确认决策

下列六项均为用户本轮明确确认，不使用 Agent 主观把握代替确认。后续“先自己细化”的
授权用于整理已确认方案的功能和验收要求，不重新打开既有决定。
设计中的 D7、D8 为授权范围内的技术落实，主观把握明确超过 85%；依据为当前返回值
调用点及 Delivery 读取边界。它们不是用户逐项批准或测试概率，没有未决业务取舍。

| 编号 | 采用方案及主要取舍 | 来源与状态 |
| --- | --- | --- |
| D1 | 完整小链优先，通常复用已有业务切片；必要共享依赖随首链落地，后续复用身份；Agent 按真实依赖决定阶段边界 | 用户本轮确认及后续澄清 |
| D2 | 问题只暂停受影响内容及其依赖，其他继续；需依据实际共享引用判断影响，不暂停全部后续阶段 | 用户本轮确认 |
| D3 | 保留工具内回执身份／终态／版本确认；取消成功后例行全量／逐条写入核验；保留业务读取、最终关联检查、受影响复查及异常对账 | 用户本轮确认 |
| D4 | 首链尽早反馈，后续时机及公开选题由 Agent 按价值判断；不固定每阶段问答或所有反馈节点 | 用户本轮确认 |
| D5 | 复用现有反馈入口，实际读取期间暂停本轮新 dry-run/apply 提交，其他准备继续；接受有界提交等待，不建设更细并发状态绑定 | 用户本轮确认 |

#### 4. 验收标准与证据边界

| 编号 | 场景 | 应满足的行为 |
| --- | --- | --- |
| A1 | 首条完整小链及必要共享依赖就绪，后续链尚未形成详细候选／计划 | 首链按当前获批计划安全执行；全局范围和待办保留，后续复用身份；不等全部共享基础完成 |
| A2 | 当前阶段获批候选含必要关系，但执行计划漏项 | 应用前指出阶段覆盖缺口并补齐；不以定义数量、部分 applied 或题目通过代替完整计划 |
| A3 | 多个依赖有序的计划正常明确成功应用 | 保留身份／终态／版本确认并继续；无逐批全量读模型或逐条计划比对门；业务读取和语义结论分别记录 |
| A4 | 首条可消费小链就绪，或后续新增关键规则／共享语义 | 实际取得获准公开题的治理读取及回答；按价值选题，不等待最终 handoff，不要求所有阶段都问答 |
| A5 | 公开反馈期间仍在准备下一阶段，或实际发生绑定变化 | 暂停本轮新 dry-run/apply，其他准备继续；变化后的旧反馈记过期并保留，不混用状态或建立新并发框架 |
| A6 | 时间口径等局部错误，及共享概念影响多阶段两个对照 | 分别限制真实影响范围；无依赖内容继续，修正仍经审核和 dry-run/apply，复核受影响题／关联，问题未解决不记通过 |
| A7 | dry-run 通过、写入未确认、明确拒绝，以及业务读取发现成功回执对应漏写 | 分别保持仅验证、原身份恢复、可修正反馈、平台缺陷；不冒称完整成功，不换 key 重放，也不追加常驻全量核验 |
| A8 | 阶段已应用但未问答，全局仍有未应用内容／未查关联 | 可沿真实依赖推进，阶段反馈仍待验证；全局缺口未关闭不声称交付完整；最终实际关联及跨切片核对保留 |
| A9 | 局部公开反馈或生产自查通过，随后正式验收 | 完整冻结分母、公开／隐藏隔离及独立只读判定保持；未知、PARTIAL／REVISE 按原规则，局部成功不提升最终结论 |

文档检查只证明本条边界与 D1—D6 一致、链接和格式可用，不证明运行行为已改变。
后续实现验证须同时覆盖取消重复写入核验及保留必要语义检查／恢复；真实阶段反馈、
模型质量及提速收益须从新的获准运行取得，现有工程 PASS 和代码阅读不替代。
