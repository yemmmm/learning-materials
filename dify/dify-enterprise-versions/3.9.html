Dify Enterprise / LTS 长期支持线

3.9.x LTS

Dify 企业版 3.9 是当前的长期支持（LTS）线，覆盖 3.9.0 → 3.9.8 共 9 个版本。 3.9.0 作为 LTS 首发引入了 HITL 人工审核、Celery worker 化执行等重磅能力；后续版本以安全加固、性能调优（TTFE）和 Redis 高可用为主。 对应社区版 1.13.x。

v3.9.0
LTS Breaking · 3 8 新特性 · 13 修复 停机 · 无
发布 2026-03-31 社区版 1.13.3 企业层 0.16.0 支持至 2026-12-31
8 新特性
Human-in-the-Loop：人工输入节点HITL · 工作流
工作流现在可以在任意节点暂停，等待人工审核后再继续。新增的 Human Input 节点让你在流程图里直接插入审核步骤：审核者可查看 AI 输出、编辑变量，并通过自定义按钮（如"批准 / 拒绝 / 升级"）决定流程走向。表单通过 Webapp 或邮件送达，暂停的运行在收到响应后自动恢复。
工作流执行迁入 Celery Worker架构 · 可扩展性
基于工作流的流式执行和高级聊天执行从 API 进程移到了 Celery worker，提升了可扩展性，也是上面 HITL 暂停/恢复的前提。部署必须新增 workflow_based_app_execution 队列（Helm values 或 Docker Compose 都要有 worker 消费这个队列），否则流式执行不会被处理。
MCP 工具用量元数据提取MCP · 可观测性
MCP 工具集成现在会从工具响应中提取并暴露 token 与成本用量元数据，可在工作流运行中追踪和归因 MCP 服务的资源消耗。
Service API：终端用户查询接口Admin / Service API
新增 Service API 接口，可在指定租户和应用范围内查询终端用户，便于编程化构建用户管理集成和审计流程。
Admin API：批量 DSL 导入导出Admin API
Admin API 新增批量导入导出应用 DSL 文件的接口，加速应用在工作区之间的迁移、备份和批量配置。
Helm：Celery 队列拆分，专用嵌入 WorkerHelm · 知识库
Helm Chart 支持将 Celery 队列拆分为独立配置资源的专用 worker。管理员可为知识库嵌入（embedding）任务单独分配计算资源，解决大文档处理极慢的问题。
荷兰语（nl-NL）支持本地化
后端语言映射和前端本地化资源新增荷兰语。
企业遥测改进可观测性
企业特定的遥测增强整合进主代码库，为企业版部署提供更好的可观测性和用量追踪。
13 问题修复
安全登出后 Access Token 仍有效：用户登出后令牌未失效，现已在登出时正确撤销；多组件 CVE 修复（API / 企业采集器 / 前端 / sandbox / web）。
插件企业管理台插件版本升降级返回 404（已分配工作区的插件）；插件管理页未显示未分配工作区的已装插件；插件版本变更后凭据在工作流编辑器中不可选（不再需重新分配）。
凭据凭据策略 API 并发读取优化解决高延迟；PUT 接口曾接受无效插件 ID（如畸形三段式），导致后续读写全部 500、需手工修库。
工作流/APIOTel 端点 URL 校验曾拒绝带路径的有效 URL（如 LangSmith）；OpenAI 新模型凭据（GPT-5.2+ 已废弃 max_tokens 改用 max_completion_tokens）报 400；Helm 升级后工作区列表加载缓慢。
Helm/运行时自定义 CA 证书未下发到采集器导致出站 TLS 失败；创建用户组误报"已存在"+500；企业组件 Go 运行时升级，提升性能并修复标准库安全问题。
! 升级影响（含破坏性变更）
⚠ 破坏性变更，升级前需处理：

• 内置 MinIO 替换为企业对象存储（OSS）：因开源 MinIO 不再活跃维护，Helm Chart 中捆绑的 MinIO 被替换为轻量内置企业 OSS。依赖原 MinIO 的部署需检查 Helm values 的存储配置。

• 移除若干向量库与追踪集成：AnalyticDB、Tablestore、ClickZetta 向量库集成与 Wandb Weave 追踪集成不再包含在当前 LTS 企业版镜像中。仍需使用的可改用社区版镜像（需自行承担安全风险）。

• Sandbox：Python 3.10 → 3.14：代码执行沙箱镜像升级，自定义工作流代码、锁定的依赖、第三方 wheel 可能需更新并重新测试后再上生产。

v3.9.1
LTS Breaking · 3 2 新特性 · 0 修复 停机 · 无

2 新特性
数据库配置：每服务独立的外部数据库凭据部署 · 安全
企业部署现在可以为每个外部数据库单独配置用户名和密码，不再所有服务共享一套凭据，更易满足严格的数据库访问策略和服务级凭据隔离要求。
Azure Blob：托管标识支持存储 · Azure
Azure Blob 存储集成现在支持用 Azure 托管标识（Managed Identity）认证。Helm Chart 也增加了企业审计和插件守护进程工作负载所需的 pod 标签与 service account 配置，无需再存储静态凭据。
! 升级影响
⚠ 移除集成需镜像审查 + 两个 hotfix：

• 同 3.9.0，AnalyticDB / Tablestore / ClickZetta / Wandb Weave 不在标准企业 dify-api 镜像中，需用 dify-ee-api-insecure:3.9.1 替代（自担风险）。3.9.2 会把 AnalyticDB 与 Tablestore 加回标准镜像。

• OpenSearch 向量库触发 ImportError：使用 patched 镜像 dify-ee-api:3.9.1-hotfix-20260422。

• 工作流运行实例化性能 hotfix（缓存凭据）：dify-ee-api:3.9.1-hotfix-20260423-2。

为缩小攻击面，Weights & Biases（wandb）追踪与 ClickZetta 向量库不再包含在默认 API 镜像中。仍需这两个集成的，使用 dify-ee-api-insecure:3.9.2（保留旧行为，但带额外已知漏洞）。
