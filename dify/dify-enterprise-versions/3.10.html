3.10.0

3.10.0 是一条 维护分支版本，且不可跳过（Non-skippable，升级路径必须经过它）。 这是一个面向生产运维的版本：把企业级可观测性、Redis 高可用、外部向量库与 K8s 弹性扩缩容一次性补齐。 对应社区版 1.14.1、企业层 0.17.0。升级需停机，含破坏性 DB 迁移。

7 新特性
企业可观测性：OpenTelemetry 追踪与指标OTel · 生产运维
企业后端服务现在为远程调用和数据库访问统一发出 OpenTelemetry 追踪与指标，便于在生产中精确定位性能瓶颈。通过标准 OTEL_* 环境变量配置，Helm 和 Docker Compose 模板均已更新。
Redis Sentinel 与 Redis Cluster 支持高可用 · Redis
企业 Go 服务支持 Redis Sentinel（高可用 Redis）；EVENT_BUS 组件可额外配置使用独立的 Redis Cluster。Helm 与 Docker Compose 用统一的 Redis/MQ schema 支持这些模式。注意：端到端 Redis Cluster 尚未完全支持——目前仅 EVENT_BUS 能独立配置 Redis Cluster。
Helm：外部 PGVector 向量数据库Helm · 向量库
Helm Chart 支持配置外部 PGVector 实例作为向量库后端，运维可自主掌控向量存储的部署位置与配置。
Kubernetes：DifyPlugin Scale 子资源，对接 HPAK8s · 弹性
DifyPlugin 自定义资源实现了 Kubernetes scale 子资源，客户可直接把 HPA（水平 Pod 自动扩缩容）接到插件部署，无需自定义控制器逻辑。
Kubernetes：动态 Kubeconfig 令牌轮换K8s · 凭据
企业服务支持自动 kubeconfig 重载，支持动态令牌轮换场景。此前 kubeconfig 认证不能正确处理令牌刷新，凭据轮换需要重启 pod。
插件管理：全选工作区管理台 · 效率
企业管理台插件管理页支持一次全选所有工作区来安装或分配插件，大型部署不再需要逐个工作区点选。
工作流：图初始化性能改进性能 · 工作流
优化图初始化逻辑，降低多节点复杂工作流的启动延迟。
13 问题修复
安全模型凭据 API SQL 注入防护：CreateCredential / UpdateCredential gRPC 端点对 customer_model_type 做严格白名单校验。此前畸形值（含 SQL 注入字符）会被写入 provider_models，导致下游所有模型相关 API 报错且需手工修库。
离线/插件离线（air-gapped）环境：管理后台安装/分配插件不再联系 marketplace.dify.ai（消除 context deadline 超时）；知识库转管道在离线模式不再触发 marketplace 查询（消除 500）。插件安装现在兼容 uv 包管理器；插件守护进程 decode 端点参数位置（body→query/form）修正。
凭据/许可工作区凭据多默认值竞态（多人同时设默认）；pod 重启触发 License 误提示重激活（cluster_id 唯一约束冲突，现跳过重复插入）。
数据/模型多模态知识库图片浏览器不可访问（URL 用了内部 k8s 主机名 dify-api:5001，改用外部域名）；编辑模型凭据时上下文长度被清空；Dify 升级后密码重置失败（SQLAlchemy session）。
部署/可观测Collector 因 Postgres 密码含 # 启动崩溃（误解析为端口分隔符）；OTLP 端点校验拒绝带 scheme 的 URL（现已接受 http:// / https://）。
UI代码节点环境变量/输入参数引用在编辑器渲染错误（运行时正常，仅 UI 混乱）；知识库上传对话框最大文件数显示不准。
! 升级影响（破坏性 · 需停机）
⚠ 本版本需停机，含两处需手动处理的破坏性变更：

• Dify DB：model_type 旧值迁移。CE 1.14.1 强制规范数据库中的 model_type 值。若你的库含旧值（text-generation / embeddings / reranking），升级后需在 Dify API 容器内运行 flask data-migrate legacy-model-types。企业 DB 本身无需迁移，完整步骤见 Upgrade Guide 的 Migration Notes。

• Docker Compose：新 env_file 架构（对齐 CE 1.14.1）。若用"除 .env 外替换全部文件"的标准流程升级，无需额外操作；若手工管理文件，须确保 envs/enterprise/* 在 .env 中正确设置，否则 Docker Compose 拒绝启动。
